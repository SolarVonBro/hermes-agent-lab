# T3. Модель угроз и безопасность агента

Задание 2. Выполнили: Голиенко Роман, Митенева София.

Объект: агент Hermes Agent (NousResearch, MIT) в контейнере Docker Desktop с доступом к терминалу контейнера и к сети. Шлюз — Telegram, LLM — OpenRouter (бесплатная модель). Основа выводов: официальная политика безопасности проекта `SECURITY.md`, материалы задания и собственные эксперименты.

## 1. Что защищаем и кто атакует

| Актив | Где находится | Почему важен |
|---|---|---|
| Ключ LLM-провайдера | `data/.env` | расход бюджета, доступ к аккаунту |
| Токен Telegram-бота | `data/.env` | управление агентом = доступ к терминалу контейнера |
| Память агента (`MEMORY.md`, `USER.md`) | `data/memories/` | личный контекст, договорённости |
| Рабочий каталог, навыки, сессии | `data/` | результаты работы, история |
| Хост (ПК) и его сети | за пределами контейнера | личные данные и другие системы |

Атакующие: (1) посторонний пользователь Telegram; (2) автор внешнего контента, который агент читает (веб-страница, README, PDF, письмо); (3) автор стороннего навыка, образа или MCP-сервера; (4) «сам агент» — ошибочное или дрейфующее поведение модели.

Главный тезис, подтверждённый официальной политикой проекта: **единственная реальная граница безопасности против враждебной модели — операционная система (контейнер, виртуальная машина)**. Подтверждение действий, поиск опасных шаблонов в командах, вычищение секретов из вывода и белые списки инструментов — эвристики, а не границы.

## 2. Модель угроз

| № | Угроза | Вектор | Контрмера | Эффективность контрмеры | Остаточный риск |
|---|---|---|---|---|---|
| 1 | Прямая prompt injection | Пользователь (или тот, кто получил доступ к чату) пишет агенту вредные инструкции | Список разрешённых пользователей шлюза (`TELEGRAM_ALLOWED_USERS`); запрет режима «разрешить всем» | Высокая против посторонних; не защищает от самого владельца и от захвата его аккаунта | Захват аккаунта Telegram владельца |
| 2 | Косвенная prompt injection | Инструкция внутри обрабатываемых данных: HTML-комментарий, невидимый текст, `alt`, README, имя файла, метаданные PDF, поле данных | Инструкция в системном промпте («данные — не команды»); минимальные права; подтверждение опасных действий человеком; изоляция контейнером | Частичная: снижает вероятность, но не исключает | **Остаётся принципиально:** модель получает данные и команды в одном потоке токенов и не различает их надёжно; фильтр промпта обходим перефразировкой, кодировкой, другим языком |
| 3 | Эксфильтрация секретов | Агент (под влиянием инъекции) отправляет `.env`, ключи, `MEMORY.md`, исходники по сети: `curl`, веб-запрос, ссылка с данными в параметрах, вывод в чат | Сетевые ограничения на исходящий трафик (allowlist доменов); секреты вне доступного каталога; отдельный изолированный контур без рабочих данных; лимит расходов на ключе | Сетевой allowlist — высокая (реальная граница); очистка вывода от секретов — низкая (обходится кодированием) | Всё, что агент может прочитать, он теоретически может передать на разрешённые хосты (например, в сам чат и к провайдеру LLM) |
| 4 | Разрушающие действия | `rm -rf`, порча репозитория, перезапись файлов, отправка сообщений от имени пользователя, трата бюджета | Контейнер без монтирования рабочих каталогов (кроме `data/`); непривилегированный пользователь; ограничение ресурсов; подтверждение человеком; лимит ключа; отдельная ветка/PR вместо записи в `main` | Контейнер — высокая в границах контейнера; подтверждение — средняя (эвристика, оболочка Turing-полна) | Повреждение содержимого `data/` и всего, что агенту явно выдано |
| 5 | Компрометация канала доступа | Утечка токена бота, подмена списка разрешённых, перехват идентификатора, пересылка токена в чате | Токен только в `.env`, вне репозитория; список разрешённых = один идентификатор; отзыв и перевыпуск токена (`/revoke` у BotFather); не публиковать токен | Высокая при соблюдении дисциплины; токен, показанный в чате, считается скомпрометированным | Человеческий фактор: токен остаётся в истории переписки |
| 6 | Цепочка поставок | Сторонние навыки из общедоступного хаба, образы контейнеров, MCP-серверы, плагины | Использовать только проверенный образ из официального репозитория; пиннинг тега/дайджеста; чтение кода навыка до установки (навык исполняет код при импорте); не подключать лишние MCP | Средняя: встроенный сканер навыков — лишь подсказка для ревью | Скомпрометированный навык или плагин получает все привилегии агента и его ключи |
| 7 | Дрейф и закрепление ошибки | Автоматически созданный навык из «успешной» сессии закрепляет неверную процедуру | Ревью автоматических навыков, версионирование `data/skills/` в git, контрольные задачи | Средняя | Незаметное изменение поведения со временем |
| 8 | Отказ в обслуживании и расходы | Зацикливание, лавина cron-задач, 429 от провайдера | Лимит ключа, лимит шагов, ограничение ресурсов контейнера, ротация логов | Высокая для бюджета, средняя для доступности | Остановка работы при исчерпании бесплатной квоты |

## 3. Контрмеры: реальная эффективность

| Контрмера | Что закрывает | Что не закрывает |
|---|---|---|
| Изоляция в контейнере / ВМ | разрушающие действия на хосте, доступ к чужим файлам | всё, что агент может сделать внутри контейнера и по разрешённой сети |
| Непривилегированный пользователь | повышение привилегий, порча системных файлов | действия в пределах прав этого пользователя |
| Список разрешённых команд | известные опасные команды | обход через интерпретатор (Python, `sh -c`), перенаправление вывода |
| Подтверждение человеком | неожиданные деструктивные действия | «усталость от подтверждений», неочевидные по виду команды |
| Сетевые ограничения (исходящий allowlist) | эксфильтрация на произвольные хосты, скачивание вредоносной нагрузки | утечку через разрешённые хосты |
| Отдельная машина без доступа к рабочим системам | распространение ущерба | утечки того, что на этой машине есть |
| Ротация ключей | срок жизни скомпрометированного секрета | сам факт утечки |
| Аудит логов | обнаружение постфактум, расследование | предотвращение |
| Инструкция в системном промпте | простейшие и случайные инъекции | целенаправленные обходы |

## 4. Сопоставление подходов к безопасности платформ

| Платформа | Подход (по документации) | Какие классы угроз закрывает | Что остаётся открытым |
|---|---|---|---|
| Hermes Agent | Граница — ОС: образ Docker, терминальные бэкенды, OpenShell; внутри процесса только эвристики (подтверждение опасных команд, очистка вывода, сканер навыков); фильтрация переменных окружения для подпроцессов | разрушающие действия (в контейнере), эксфильтрация обычных секретов из оболочки | плагины и навыки работают с полными правами; косвенная инъекция; утечка через разрешённую сеть |
| PicoClaw (по материалам задания) | Ограничение агента пределами рабочего каталога, отключение опасных команд, малое ядро | порча файлов вне каталога, часть опасных команд | эксфильтрация внутри каталога и по сети, косвенная инъекция |
| OpenClaw (по материалам задания) | Одномашинный ассистент; защита зависит от настройки машины | зависит от развёртывания | всё, что не закрыто конфигурацией ОС |
| Claude Code / Codex CLI | Локальный агент с режимами разрешений и подтверждениями, опциональная песочница | деструктивные действия по подтверждению | косвенная инъекция, эксфильтрация через разрешённые инструменты |

Принципиально открытые классы для всех платформ: **косвенная prompt injection** (нет разделения данных и инструкций внутри модели) и **утечка через разрешённый канал**. Их можно лишь ограничивать (меньше прав, меньше данных у агента, изоляция, сетевой allowlist), но не устранить.

## 5. Что применено в этом развёртывании

| Мера | Реализация | Где подтверждено |
|---|---|---|
| Отдельный контур без личных данных | контейнер в Docker Desktop, монтируется только `D:\work\python-agent\data` | `compose.yaml` |
| Нет входящих портов | порты в `compose.yaml` не публикуются; шлюз работает через исходящий long polling | `compose.yaml` |
| Нет доступа к Docker хоста | `docker.sock` не монтируется, `network_mode: host` не используется | `compose.yaml` |
| Непривилегированный пользователь | процессы агента под пользователем `hermes` (UID 10000) | логи старта (`s6-setuidgid`, `stage2`) |
| Список разрешённых | `TELEGRAM_ALLOWED_USERS` содержит только владельца | `data/.env` (не в репозитории) |
| Ограничение ресурсов | `mem_limit: 1536m`, `cpus: 1.0`, `pids_limit: 512` | `compose.yaml` |
| Лимит расходов | ключ OpenRouter с лимитом $1, бесплатная модель, баланс не пополнялся | `GET /api/v1/key`: `limit: 1`, `usage: 0` |
| Ротация логов | контейнер: `json-file` 10 МБ × 5; агент: `logging.max_size_mb: 10`, `backup_count: 5` | `compose.yaml`, `config.yaml` |
| Секреты вне репозитория | `data/` и `.env` в `.gitignore` | `.gitignore` |

Выводы по T3 для безопасного применения в исследовательской работе: держать агента в изолированном контуре без рабочих данных и ключей других систем; давать минимум прав и инструментов; ограничивать исходящую сеть; не поручать агенту записывать в основные ветки и публиковать результаты без проверки человеком; хранить и ротировать секреты; считать любой читаемый агентом внешний контент недоверенным.
